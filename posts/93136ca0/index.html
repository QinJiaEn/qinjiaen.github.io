nginx与frp的内网服务器实战

发表于2025-12-25|更新于2026-06-10|入职后(数据脱敏处理)
|阅读量:

xxxx(脱敏处理)管理服务平台 - Nginx 与 FRP 穿透配置调整文档

文档概述

本文档基于当前的部署架构（内网服务器 + FRP 内网穿透 + 阿里云公网服务器），梳理了前期配置中存在的核心问题、完整调整方案、操作步骤及验证方法，确保前端页面、后端接口通过二级域名正常访问，同时保障生产环境安全性与稳定性。

部署架构说明

  • 内网服务器：部署前端静态资源、后端 Jar 包（9094 端口）、Nginx（80 端口）
  • FRP 穿透：内网 Nginx（80 端口）→ 阿里云 8888 端口；后端 Jar 包（9094 端口）→ 阿里云 9094 端口
  • 阿里云服务器：部署 Nginx（80 端口），通过二级域名代理转发流量到内网 FRP 端口
  • 访问链路：用户 → 阿里云 Nginx（二级域名）→ FRP 穿透 → 内网 Nginx → 前端 / 后端服务

一、前期配置核心问题汇总

1. FRP 配置问题（已提前修复）

  • 端口冲突：内网 FRP 配置中，web_java（9094）与 nginx_tax（9094）共用远程端口，导致穿透失效
  • 修复方案：将内网 Nginx 穿透端口改为 8888，后端 Jar 包保留 9094，避免冲突

2. 阿里云 Nginx 配置冲突（核心问题）

  • 接口转发冲突：declare.xxxxx(脱敏处理).com 同时配置 location /（转发内网 8888）和 location /prod-api（直接转发后端 9094），精确路径优先级更高，破坏完整链路
  • 冗余配置：静态资源缓存规则在通用转发下无效，增加配置复杂度
  • 端口错误：xxxxx(脱敏处理).com 的 /prod-api 转发到旧端口 9092，接口访问失败

3. 内网 Nginx 配置问题

  • 权限问题：普通用户执行 Nginx 命令无权限访问日志、PID 文件，导致校验 / 重启失败

4. 前端部署问题

  • 前端更新后未正确替换内网资源，或未重启内网 Nginx，导致新页面不生效

二、配置调整方案（分服务器）

（一）内网服务器 Nginx 配置调整

1. 修正后完整配置（/etc/nginx/nginx.conf）

2. 关键修改点说明

  • 关闭 autoindex on → autoindex off：禁止目录浏览，避免文件泄露
  • 保留接口转发逻辑：确保前端 /prod-api 请求正确转发到后端 9094 端口
  • 保留路由重写规则：解决 Vue 前端页面刷新 404 问题

（二）阿里云服务器 Nginx 配置调整

1. 原配置问题

  • 接口转发冲突：declare.xxxxx(脱敏处理).com 同时存在通用转发与接口转发，链路混乱
  • 端口错误：xxxxx(脱敏处理).com 的 /prod-api 转发到 9092（旧端口），应改为 9094
  • 相对路径风险：alias html/webtax 改为绝对路径，避免 Nginx 识别失败
  • 冗余配置：删除无效的静态资源规则与重复接口转发

2. 修正后完整配置（/usr/local/nginx/conf/nginx.conf）

3. 关键修改点说明

  • 冲突修复：declare.xxxxx(脱敏处理).com 仅保留 location / 通用转发，删除重复接口转发，确保链路完整
  • 端口修正：xxxxx(脱敏处理).com 的 /prod-api 转发阿里云的9092端口,
  • 路径优化：所有 alias 改为绝对路径，避免 Nginx 路径识别失败
  • 安全优化：关闭所有 autoindex on，禁止目录浏览
  • 冗余清理：删除无效的静态资源规则，简化配置

五、常见问题排查

1. Nginx 权限报错（Permission denied）

  • 问题：执行 nginx -t/systemctl restart nginx 提示权限不足
  • 解决方案：所有 Nginx 操作加 sudo，如 sudo nginx -t、sudo systemctl restart nginx

2. 页面 404 错误

  • 原因：前端资源路径错误、Nginx alias 路径不匹配
  • 解决方案：检查内网 /usr/share/nginx/html/webtax 目录是否存在，dist 是否正确重命名为 webtax

3. 接口 502 错误

  • 原因：后端 Jar 包未启动、FRP 9094 端口穿透失败
  • 解决方案：内网执行 ps -ef | grep java 确认 Jar 包运行，检查 FRP 仪表盘 9094 端口状态

4. 页面刷新 404 错误

  • 原因：缺少 Vue 路由重写规则
  • 解决方案：确保内网 Nginx 配置中存在 @router_webtax 重写规则

六、关键注意事项

  1. 权限规范：Linux 下 Nginx 监听 80 端口，所有管理操作必须加 sudo
  2. 配置校验：修改 Nginx 配置后，必须先执行 sudo nginx -t 校验语法，再重启
  3. 安全原则：生产环境禁止开启 autoindex on，避免文件泄露
  4. 链路完整：阿里云 Nginx 仅负责转发，所有逻辑（接口、路由）由内网 Nginx 处理
  5. 前端更新：新页面发布后，仅需替换内网资源并重启内网 Nginx，阿里云 Nginx 无需操作

文档总结

本次调整核心解决了 Nginx 配置冲突、安全风险、权限问题，优化了访问链路，确保：

  1. 二级域名 declare.xxxxx(脱敏处理).com 可正常访问前端页面与后端接口
  2. 生产环境关闭目录浏览，提升安全性
  3. 前端更新流程简化，仅需内网操作即可生效
  4. 所有配置逻辑清晰，无冗余、无冲突，便于后续维护

按文档步骤执行后，若仍有异常，可通过 Nginx 错误日志（/var/log/nginx/error.log 内网(内网需要有权限)、/usr/local/nginx/logs/error.log 阿里云）定位具体问题。
